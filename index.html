2 反扒措施分析
核心发现：该网站采用"路径白名单制"——仅允许首页 / 和带有有效UUID的详情页 /proj/tc/{uuid} 访问，其余所有非标准路径（robots.txt、sitemap.xml、目录列表、带参数URL）全部直接断连 ERR_CONNECTION_CLOSED。
# 反扒措施 技术细节 实测结果 严重度
1 路径白名单 仅 / 和 /proj/tc/{uuid} 可访问 测试30+路径全部 ERR_CONNECTION_CLOSED 高
2 robots.txt 封锁 访问 /robots.txt 直接断连 连接被拒绝 中
3 sitemap.xml 封锁 访问 /sitemap.xml 直接断连 连接被拒绝 中
4 目录列表禁用 /proj/、/proj/tc/ 等目录路径全部断连 连接被拒绝 中
5 URL UUID 防遍历 项目ID为32位随机UUID，无法自增遍历 需先获取UUID才能访问详情页 中
6 调试器检测 JS中包含 endebug() 反调试函数，检测Firebug 当前已注释禁用 // endebug(false, ...) 低
7 Referer 策略 <meta name="referrer" content="no-referrer"> 不发送Referer头，不影响爬取 低
未检测到的反扒措施： 频率限制 IP封禁 验证码 JS渲染验证 User-Agent检测 Cookie验证

连续3次快速请求同一页面均成功，未触发任何限制。

6 突破策略总结
1 浏览器网络请求分析
通过浏览器 DevTools Network 面板，捕获页面 AJAX 请求，发现后端 API 端点 /getZCData
2 API 参数逆向
通过页面内联 JS 脚本中的 getZCProj() 函数，逆向出 API 参数格式：assetsType 字段，空字符串=全部
3 HTML 表格解析
API 返回 HTML 表格片段而非 JSON，通过解析 <tr data-proId="UUID"> 获取项目 UUID 和完整字段
4 详情页直接访问
获取 UUID 后，可直接访问 /proj/tc/{uuid} 获取 SSR 渲染的完整详情页，无需 JS 执行
